# Autorunne 0.6.34 State Reliability Design

**Status:** Approved scope

**Date:** 2026-08-22

**Release target:** `0.6.34`

## Product intent

Autorunne already solves a useful problem: an AI agent can enter a repository and immediately understand what has been completed, what is active, and what should happen next. Version 0.6.34 preserves that interaction model and strengthens the local state layer underneath it.

This is a reliability patch, not a product rewrite. A user upgrading from 0.6.33 should keep using the same commands and the same `.autorunne/views/*` handoff files.

## Evidence motivating the patch

The current 0.6.33 implementation has four concrete reliability gaps:

1. State mutation is a read-modify-write sequence without a cross-process lock. Concurrent commands can read the same old state, overwrite one another, or observe a partially written JSON file.
2. `compact_memory()` writes `.autorunne/archive/YYYY-MM.md` with `write_text()`. A second compaction in the same month replaces the first archive.
3. `read_json()` directly calls `json.loads()`. A malformed primary state file prevents both normal commands and `doctor` from opening the workspace, even when a prior valid copy could have been retained.
4. Release metadata is inconsistent: `pyproject.toml` is 0.6.33 while `autorunne.__version__` and `WorkflowConfig.version` are 0.6.31. One CLI test also writes an update-check cache in the checkout instead of an isolated temporary directory.

## Scope

### Included

- Serialize state-changing Autorunne operations across threads and processes.
- Replace direct JSON writes with same-directory atomic replacement.
- Keep one last-known-good backup for recoverable JSON state.
- Recover automatically from a malformed primary JSON file when its backup is valid.
- Fail closed with an actionable error when neither primary nor backup is valid.
- Make event appends durable and prevent compaction rewrites from racing with event writers.
- Preserve all same-month archive history and make a repeated compaction batch idempotent.
- Align package/runtime/config/integration version reporting at 0.6.34.
- Isolate update-check tests from the real checkout cache.
- Add focused regression tests, full-suite verification, build verification, release notes, and a Codex review handoff.

### Excluded

- Daemon duration, polling interval, scan performance, and dependency-tree filtering.
- Git worktree adoption or `.git` file support.
- New database formats, SQLite migration, cloud synchronization, or remote locking.
- Changes to the user-facing task model, CLI command names, handoff view structure, or compaction thresholds.
- Publishing to GitHub, creating a tag/release, uploading to PyPI, or changing external systems.

These excluded items are candidates for 0.6.35 or later and must not be mixed into this patch.

## Architecture

### 1. One persistence boundary

Create `src/autorunne/core/persistence.py`. It owns four concerns only:

- a re-entrant workspace lock;
- atomic text replacement;
- atomic JSON replacement with a valid backup;
- JSON recovery and explicit corruption errors.

`src/autorunne/core/paths.py` remains the public path/config helper and delegates its JSON/text writes to the persistence module. Business-state transformations remain in `state_engine.py`.

This keeps file-system safety separate from task and handoff semantics.

### 2. Re-entrant workspace lock

The lock file is `.autorunne/runtime/state.lock`. A process must hold the lock for the complete read-modify-write-render operation, not only for the final `write_text()` call.

Required behavior:

- Serialize threads in one Python process with a per-workspace `threading.RLock`.
- Serialize processes with a standard-library OS file lock.
- Use `fcntl.flock()` on POSIX and a small `msvcrt.locking()` adapter on Windows.
- Support nested Autorunne calls in the same thread without deadlocking. For example, `finish_task()` may call `save_workspace_state()`, `append_event()`, and `render_views()` while already holding the workspace lock.
- Default to a 10-second timeout with short polling.
- Raise `StateLockTimeoutError` with the repo path and a retry instruction when the lock cannot be acquired.
- Release automatically on context exit and process termination. The lock file itself may remain; lock ownership is the OS lock, not file existence.

Public state mutators in `state_engine.py` and `compact_memory()` must hold this lock around their full transaction. Read-only composite loads should also use the same re-entrant lock so they cannot observe a half-updated set of state files.

### 3. Atomic JSON write and last-known-good backup

For a target such as `sessions.json`:

1. Serialize the new payload before touching disk.
2. If the current primary exists and parses as JSON, atomically write its exact contents to `sessions.json.bak`.
3. Write the new content to a unique temporary file in the same directory.
4. Flush and `fsync()` the temporary file.
5. Replace the primary with `os.replace()`.
6. Best-effort `fsync()` the containing directory on platforms that support it.
7. Remove any leftover temporary file in `finally`.

Never copy a malformed primary over a valid backup. A backup represents the last state known to have parsed successfully.

The same atomic text primitive is used for rendered views, snapshots, config, memory summaries, and archive rewrites, but automatic JSON recovery is limited to JSON state/config files.

### 4. Recovery and fail-closed behavior

`read_json()` follows this contract:

- Missing primary: return the caller-provided default, preserving current behavior.
- Valid primary: return it unchanged.
- Malformed primary plus valid `.bak`: atomically restore the backup to the primary, then return the recovered payload.
- Malformed primary plus missing/malformed `.bak`: raise `StateCorruptionError`.

The exception message must identify both paths and tell the user to preserve `.autorunne/`, inspect the files, or restore from their own backup. It must never tell the user to delete or reset state.

Recovery is local and deterministic. It does not claim to reconstruct the newest interrupted command; it restores the latest complete JSON generation.

### 5. Event JSONL durability

`events.jsonl` stays JSON Lines; there is no format migration.

- Every append occurs while holding the workspace lock.
- Append one pre-serialized JSON object plus newline, then flush and `fsync()`.
- Compaction rewrites the retained events using atomic replacement and keeps `events.jsonl.bak` when the previous file is valid JSONL.
- `load_events()` accepts and removes only one malformed trailing fragment, which represents an interrupted append. A malformed non-final line is corruption and raises `StateCorruptionError`.
- Tail repair must itself happen under the workspace lock and use atomic replacement. It may discard only the incomplete trailing fragment, never a valid event.

### 6. Append-only, idempotent monthly archives

Monthly file names remain `.autorunne/archive/YYYY-MM.md` for compatibility.

Each compacted month produces a deterministic batch fingerprint from the canonical JSON representation of that month’s old sessions and events. The archive section begins with:

```markdown
<!-- autorunne-archive-batch:SHA256 -->
## Compaction batch — TIMESTAMP
```

Rules:

- Create the top-level `# Autorunne Archive - YYYY-MM` heading once.
- Append a new batch section to existing content; never replace older sections.
- If the same fingerprint is already present, do not append it again. This makes a retry safe if a process stopped after archive persistence but before primary-state trimming.
- Rewrite the combined archive atomically rather than using an unprotected append.
- Keep the existing human-readable session and event bullets.

### 7. Version and test hygiene

- Set `autorunne.__version__` to `0.6.34`.
- Set `pyproject.toml` project version to `0.6.34`.
- Make `WorkflowConfig.version` derive from `autorunne.__version__` instead of carrying another literal.
- Continue rendering installed integration skill versions from `autorunne.__version__`.
- Add a regression assertion that package metadata, runtime version, default config, and freshly rendered integration skill agree.
- Change the CLI update-check test to use `tmp_path` explicitly so `9.9.9` is never cached in the source checkout.

## Mutation boundary

The following operations must execute their state read, mutation, persistence, event write, and render under one re-entrant workspace lock:

- workspace bootstrap and sync;
- start, checkpoint, finish, ingest, manual record, task mutation, migration, handoff repair, and integration recording;
- explicit and automatic memory compaction;
- view rendering when it repairs state.

Scanning, validation subprocesses, and network update checks should remain outside the lock wherever they already happen before entering these state-engine functions. The lock protects state persistence, not long-running business commands.

## Compatibility and migration

There is no user-triggered migration.

- Existing state files remain valid.
- `.bak` files appear lazily after the first successful replacement.
- Existing monthly archives without batch markers remain untouched. The first 0.6.34 compaction appends a marked section below the old content.
- Existing CLI output and view schema should remain unchanged except for actionable recovery/lock errors.

## Acceptance criteria

1. Forty concurrent `autorunne task add` subprocesses finish without JSON decoding errors and all forty unique tasks remain recorded.
2. Interrupt-style tests prove a reader sees either the old complete JSON or the new complete JSON, never a partial document.
3. A malformed primary plus valid backup is restored automatically by `autorunne open` and `autorunne doctor`.
4. A malformed primary plus malformed/missing backup exits nonzero with an actionable corruption message and does not overwrite either file.
5. Two compactions for the same month preserve both distinct batches.
6. Re-running the same compaction batch does not duplicate archive bullets.
7. A malformed trailing JSONL fragment is removed without losing earlier valid events; middle-line corruption fails closed.
8. Existing focused and full tests pass with update checks disabled.
9. The wheel and sdist build successfully and report version 0.6.34.
10. No daemon/worktree behavior changes and no GitHub/PyPI publication occurs.

## Delivery and review boundary

The implementer must create `CODEX_REVIEW_HANDOFF.md` at the repository root. It must list the actual branch/worktree, changed files, acceptance-criteria matrix, commands with exit codes and concise outputs, known limitations, and one final status: `COMPLETE`, `PARTIAL`, or `BLOCKED`.

Implementation completion is not release approval. Codex will independently inspect the diff and rerun proportional tests before the user decides whether to merge, push, tag, or publish.
